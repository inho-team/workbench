# Capacitor와 JS 번들 OTA

결론: 모바일 앱은 Capacitor로 빌드하며, JS 번들 OTA(Over-The-Air) 업데이트를 사용한다.

## 맥락

모바일 앱은 데스크톱 본체에 원격 접속하는 클라이언트로 작동하며, 빠른 업데이트 배포가 필요하다. 네이티브 빌드 후 스토어 심사를 매번 거치는 것은 변경 주기에 맞지 않는다.

## 대안

- Capacitor + JS 번들 OTA (선택)
- React Native + CodePush
- 매번 스토어 네이티브 앱 배포

## 결정

Capacitor와 JS 번들 OTA 방식을 모바일 앱 배포 및 업데이트 수단으로 결정한다. 이 조합은 사용자가 확정했다.

## 결과 및 감수하는 위험

- **빠른 배포:** 네이티브 앱 심사 없이 JS 번들 교체만으로 버그 수정 및 UI 업데이트를 적용할 수 있다.
- **스토어 정책:** Apple App Store와 Google Play Store 정책상 앱의 근본적인 목적이나 동작을 크게 바꾸지 않는 선에서 JS 기반 OTA 업데이트는 허용된다. 정책 위반으로 앱이 내려갈 위험을 피하려면 네이티브 코드 변경이나 새로운 권한 요구가 필요한 기능은 스토어 심사를 거쳐 업데이트해야 한다.
