# 위험과 제약

결론: omt-console은 다중 계정 활용, 모바일 원격 접속, 컨테이너 격리 등을 수행하므로 약관 위반, 보안 노출, 라이선스 등의 위험이 존재하며, 이에 대한 명확한 대응 방침을 둔다.

## 다중 계정의 서비스 약관 위반 위험
- **위험 내용:** 사용자가 API나 CLI 도구의 할당량(Quota) 제한을 회피할 목적으로 무분별하게 동일 성격의 개인 계정을 여러 개 생성하여 사용하는 경우, 해당 서비스 제공자(Google, Anthropic, OpenAI 등)의 약관(TOS) 위반으로 계정이 영구 정지될 위험이 있다.
- **대응 방향:** 앱의 계정 격리 및 전환 기능은 "업무용"과 "개인용" 등 명확하게 성격이 다른 계정을 전환하기 위한 목적으로만 한정하여 설계한다. 기본적으로 다중 계정 자동 전환 설정은 꺼(Off) 두며, 사용자가 기능을 켤 때 약관 위반 가능성에 대한 경고 문구를 UI와 README에 명시적으로 노출한다.

## 원격 접속 보안
- **위험 내용:** 모바일 기기가 데스크톱 본체에 원격 접속하기 때문에, 휴대폰을 분실하거나 접속 토큰이 유출되면 누군가 원격으로 OMT 조직과 워크트리(코드베이스)에 접근해 임의 명령을 실행할 수 있다.
- **대응 방향:**
  - **토큰 저장:** 모바일 기기의 보안 저장소(Secure Storage/Keychain)에만 토큰을 저장한다.
  - **권한 범위:** 모바일 토큰은 OMT 런타임 조회 및 승인(Approval) 등 제한된 액션만 가능하도록 최소 권한 원칙으로 발급한다.
  - **접근 제한:** Tailscale과 같은 사설 VPN 네트워크 내에서만 API가 열리도록 바인딩하여 외부망 노출을 원천 차단한다. 데스크톱 앱 내에서 발급된 세션을 즉시 폐기(Revoke)할 수 있는 UI를 제공한다.

## 스토어 OTA(Over-The-Air) 정책
- **위험 내용:** Capacitor를 활용한 JS 번들 핫 업데이트(OTA)는 모바일 스토어 심사 없이 빠른 배포가 가능하지만, Apple App Store 및 Google Play의 엄격한 가이드라인에 부딪힐 수 있다.
- **대응 방향:** OTA 업데이트는 버그 수정 및 UI/UX 개선용으로만 사용한다. 앱의 근본적인 목적(대화형 에이전트 감독)을 바꾸거나, 네이티브 코드 변경, 새로운 장치 권한(카메라, 마이크 등) 요구가 포함된 대규모 업데이트는 반드시 정규 스토어 심사 프로세스를 거쳐 배포한다.

## Windows와 macOS 환경 차이
- **위험 내용:** 파일 시스템 경로 체계(백슬래시 vs 슬래시, 드라이브 레터)와 IPC 도메인 소켓 제한 등 호스트 OS 간의 차이로 인해, 데스크톱 본체 앱이 OMT 프로세스를 호출할 때 예기치 않은 오류가 발생할 수 있다.
- **대응 방향:** 워크트리 경로 및 환경변수(CWD)를 넘길 때는 항상 크로스 플랫폼 경로 정규화를 거친다. Windows에서 컨테이너 기반 런타임을 쓸 때는 드라이브 절대 경로(`/mnt/c/Users/...` 등) 치환 래퍼를 두어 리눅스 컨테이너와의 경로 불일치 문제를 우회한다.

## 컨테이너 런타임 라이선스와 메모리 비용
- **위험 내용:**
  - **메모리 비용:** Windows나 macOS 환경에서 Docker Desktop을 구동할 경우 백그라운드 VM이 1~2GB의 메모리를 선점하므로, 여유 메모리가 적은 PC에서는 OMT 워커와 동시 구동 시 메모리 부족(OOM)을 유발할 수 있다.
  - **라이선스:** Docker Desktop, OrbStack 등은 기업 규모에 따라 유료 상업 라이선스를 요구한다.
- **대응 방향:**
  - **메모리 최적화 런타임 권장:** macOS에서는 매우 가벼운 OrbStack을, Linux에서는 데몬 없는 Podman을 우선 권장한다. Windows에서는 무거운 Docker Desktop 대신 `wsl --import` 방식의 WSL2 직접 배포판 사용을 대안으로 안내한다.
  - **라이선스 고지:** 각 컨테이너 런타임의 라이선스와 상업 사용 조건(예: Docker Desktop 유료 조건)을 사용 문서에 명확히 표기하여, 사용자가 상황에 맞는 런타임을 선택하게 돕는다. 오픈소스 완전 무상 구동을 원하는 macOS 사용자를 위해 Colima 등을 대안으로 문서화한다.
