# 로드맵

결론: omt-console 개발은 단독으로 검증 및 사용 가능한 5개의 단계(Phase 0~4)로 진행하며, 선행 조건이 해결된 후 다음 단계로 넘어간다.

## Phase 0: 저장소 기반
프로젝트의 뼈대를 잡고 코드 품질과 배포 파이프라인의 기초를 마련한다.

- **단독 쓸모:** 개발자가 코드를 작성하기 시작할 때 일관된 컨벤션과 CI 환경이 보장되어 즉시 협업을 시작할 수 있다.
- **검증 가능한 완료 기준:**
  - 빈 React 앱과 Tauri 뼈대가 생성됨.
  - 빌드(Build), 린트(Lint), 테스트(Test) 스크립트가 로컬에서 정상 실행됨.
  - GitHub Actions 등 CI가 연결되어 PR 생성 시 자동 검사가 통과함.

## Phase 1: 데스크톱 본체
데스크톱 앱이 OMT와 연결되어 채팅 인터페이스로 에이전트에게 킥오프를 지시하는 핵심 기능을 완성한다.

- **단독 쓸모:** 아직 모바일 앱이 없어도, 데스크톱 앱만으로 CLI를 대체하여 이사(Director)와 편리하게 채팅하며 조직을 제어할 수 있다.
- **선행 실측 과제: `docker exec` 에이전트 인식 테스트**
  - **내용:** 계정 격리를 위해 워커를 `docker exec`로 띄웠을 때, Orca가 전경 프로세스 이름(`docker`)을 보고 OMT 에이전트 워커로 올바르게 인식하는지 테스트한다.
  - **경로 A (성공):** 인식된다면 원래 계획대로 모든 워커와 PM을 컨테이너 런타임 위에서 실행한다.
  - **경로 B (실패):** 인식되지 않는다면, 컨테이너 계정은 OMT 헤드리스 런타임(이사 세션)에 짝지어 사용하고, 터미널 제어가 필요한 PM과 워커는 로컬 호스트 계정을 사용하는 우회 경로를 구현한다.
- **검증 가능한 완료 기준:**
  - 앱이 Orca CLI를 통해 터미널을 열고 OMT 프로세스를 실행할 수 있음.
  - 이사(Director) 세션을 헤드리스 런타임으로 연결해 채팅창에서 대화 가능.
  - 신호함(Inbox) 목록 확인 및 결정(승인/반려) 버튼 동작.
  - OOM 등 프로세스 강제 종료 시 재시작 및 상태 이어받기 기능 정상 작동.

## Phase 2: 감독 강화
시스템 자원과 계정 한도를 실시간으로 시각화하고 자동으로 조절하는 기능을 더한다.

- **단독 쓸모:** 무거운 작업을 돌릴 때 메모리 부족으로 PC가 멈추거나 계정 한도가 소진되어 작업이 끊기는 현상을 방지하여, 장시간 무인 감독이 가능해진다.
- **선행 조건:** Phase 1의 데스크톱 본체 터미널 제어가 안정적이어야 함.
- **검증 가능한 완료 기준:**
  - 상단 상태 바에 여유 메모리 크기와 현재 계정의 남은 할당량이 실시간으로 표시됨.
  - 메모리가 기준치 이하(예: 0.5GB)일 때 새 워커 작업이 슬롯 큐에서 대기 상태(Queued)가 됨.
  - 쿼터 소진 에러 감지 시, `exhausted_until` 처리와 함께 백업 계정으로 자동 전환됨.
  - PR 생성 및 CI 상태가 채팅창 타임라인에 표시됨.

## Phase 3: 모바일 원격 접속
데스크톱 본체에 종속되지 않고 모바일 기기에서도 같은 화면과 제어 권한을 갖게 한다.

- **단독 쓸모:** 외출 중이거나 PC 앞을 떠났을 때도 스마트폰으로 OMT 조직의 알림을 받고 중요한 승인을 처리할 수 있다.
- **선행 조건:** 데스크톱 앱이 로컬 API 서버 역할과 뷰(React 컴포넌트) 분리를 완벽히 지원해야 함.
- **검증 가능한 완료 기준:**
  - 모바일(Capacitor 앱)이 Tailscale 네트워크를 통해 데스크톱 API 포트에 토큰으로 인증하여 접속 성공.
  - 데스크톱과 완벽히 동일한 React 화면 컴포넌트가 모바일에 렌더링됨.
  - 놓친 결정 요청 발생 시 모바일로 푸시 알림이 도달함.
  - JS 번들 OTA(Over-The-Air)를 통해 모바일 앱 재시작 시 최신 UI 번들로 업데이트됨.

## Phase 4: 배포
사용자가 앱을 신뢰하고 쉽게 설치, 유지보수할 수 있도록 패키징을 완료한다.

- **단독 쓸모:** 개발 지식이 없는 일반 사용자도 다운로드 링크만으로 앱을 설치하고 자동 업데이트를 받을 수 있다.
- **검증 가능한 완료 기준:**
  - 데스크톱(Windows/macOS) 앱 바이너리에 코드 서명(Code Signing)이 적용됨.
  - 앱 실행 시 원격 서버의 버전을 확인하고 자동 업데이트(Auto Update)를 수행함.
  - 모바일 앱이 내부 가이드라인(약관, OTA 정책 등)을 충족하여 스토어 심사에 통과(또는 TestFlight/오픈 베타 배포)함.
